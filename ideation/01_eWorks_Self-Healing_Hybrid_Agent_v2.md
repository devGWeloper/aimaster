### 프로젝트 명

eWorks Self-Healing Hybrid Agent: 레거시 모듈을 스스로 이해·실행·수리하는 Jev·LLM 하이브리드 업무 에이전트

### 배경 및 문제 정의

* 현재 상황 (As-Is): 사내 업무 시스템(eWorks)은 문서화가 부족한 레거시 모듈(결재·경비·근태·구매·회의실·조직)의 묶음이며, 업무 에이전트를 연동하려면 개발자가 모듈마다 툴 래퍼(API 스펙·JSON 스키마)를 수작업으로 만들어야 함. 에이전트는 등록된 툴에 JSON 메시지를 보내는 수준에 머물러 있고, 모든 판단을 대형 LLM에 의존하며, 실패 시 개발자가 로그를 확인해 프롬프트·툴 코드를 수동으로 수정하는 구조

* Pain Point:
  * 시간: 단순 조회에도 LLM 생성 대기로 응답 지연 발생, 레거시 신규 기능 하나를 에이전트에 연결하는 데 수일 소요
  * 비용: 전체 요청의 대부분을 차지하는 단순 판단에 고비용 LLM 호출 소모, 툴 래퍼 개발·유지보수 공수 지속 발생
  * 품질: 레거시의 암묵적 규칙(코드값, 날짜 형식, 호출 순서)을 래퍼가 놓치면 같은 유형의 실패가 반복되며, 여러 모듈을 엮어야 하는 요청은 단일 툴 호출로 처리 불가

* 기회 요인:
  * 2026년 9월 텍스트 대신 확률이 붙은 구조화 판단을 반환하는 System One 모델(Jev)이 등장해, 단순 판단을 수십~수백 배 빠르고 저렴하게 처리 가능
  * 같은 달 Google의 RRSI 등 에이전트가 자기 하네스(프롬프트·툴·제어 코드)를 스스로 고쳐 진화하는 Recursive Self-Improvement 연구가 집중적으로 발표되며 실용 단계에 진입
  * LLM의 코드 이해·생성 능력이 레거시 소스를 읽고 호출 방법을 추론해 직접 실행 코드를 작성하는 수준(Code-as-Action)에 도달

### 목표 사용자 (Target User)

* eWorks Agent 사용자: 사내 업무 시스템에서 반복적인 조회·처리 요청을 수행하는 현업 담당자
* 에이전트 개발·운영자: 에이전트 실패 대응과 품질 개선을 담당하는 AI 엔지니어
* 레거시 시스템 담당자: 레거시 모듈을 유지보수하며, 모듈 추가·변경 시 에이전트 연동 작업을 떠안던 개발자

### 프로젝트 목표

* 정성적 목표

  * 목표 1: 사람이 툴을 등록하지 않아도 에이전트가 레거시 모듈을 스스로 탐색·이해·조합·실행하는 구조 확립

  * 목표 2: 판단 난이도에 따라 Jev(빠른 판단)와 LLM(실행 계획·추론)을 자동 분배하는 하이브리드 처리 구조 확립

  * 목표 3: 변경·비가역 작업에 대해 Dry-run, 승인, 롤백을 보장하는 안전한 실행 체계 구축

  * 목표 4: 실패 시 에이전트가 스스로 원인을 분석해 하네스를 수정·검증하고, 성공 패턴은 스킬로 축적하는 자가 개선 체계 구축

  * 목표 5: 최신 System One 모델, Recursive Self-Improvement, Code-as-Action 기술 내재화

### 핵심 기능 정의

1. Mock Legacy eWorks: 결재·경비·근태·구매·회의실·조직 6개 도메인 약 40개 함수와 SQLite 목업 DB로 레거시를 재현. 불친절한 함수명, 날짜 형식 혼재, 문서화 안 된 코드값, 호출 순서 의존, 조용한 실패(-1 반환), 숨은 부작용 등 실제 레거시의 함정을 의도적으로 포함하고, 장애 주입기로 시그니처 변경·모듈 추가 등 레거시 버전 업을 시뮬레이션

2. 모듈 자동 탐색 및 카탈로그: 레거시 소스를 정적 분석(시그니처·주석·호출 그래프·SQL·코드값)하고 LLM이 해석해 모듈 카드(파라미터 형식, 사전·사후 조건, 부작용 등급)를 생성. 샌드박스에서 프로브 실행으로 검증한 뒤 정규화·세션 처리·페이지 반복을 담당하는 어댑터 코드를 자동 생성

3. 하이브리드 판단 라우터: 사용자 요청을 Jev가 먼저 판단해 확신도가 임계값 이상이고 단일 모듈·스킬로 처리 가능하면 즉시 실행(Fast Path), 그 외에는 LLM이 실행 계획을 수립(Plan Path). 임계값은 부작용 등급별로 분리 운영

4. 모듈 실행 런타임(Code-as-Action): LLM이 어댑터를 호출하는 Python 실행 코드를 생성하고, 정적 검사 → Dry-run(변경 diff·발송 예정 메일 산출) → 승인 게이트 → 스냅샷 기반 실행·사후 조건 검증 → 실패 시 롤백 순으로 안전하게 실행. 모든 레거시 호출은 권한 범위를 강제하는 Guard Proxy를 경유하며 감사 로그 기록

5. 실패 분석 및 자가 수정 엔진(RRSI): 실패 트레이스를 유형(파라미터 형식·사전 조건 누락·잘못된 모듈 선택·계획 논리 오류·의도 오분류·레거시 변경)으로 분류하고 어댑터·모듈 카드·프롬프트·임계값 수정안을 생성. evolve셋 검증, 과적합 탐지(leakage critic), held-out셋 검증을 거쳐 일반화되는 수정만 반영하며 레거시 원본은 수정하지 않음. 모든 변경은 이력 관리 및 롤백 가능

6. 스킬 라이브러리: Plan Path로 성공한 실행 계획 중 반복되는 패턴을 파라미터화된 스킬로 일반화해 등록하고, 이후 동일 유형 요청은 Jev가 스킬을 직접 선택해 LLM 없이 처리

### 기대 효과

* 업무 효율화: 단순 액션 요청 응답 시간 50% 이상 단축, 여러 화면을 오가던 다단계 업무를 자연어 한 번으로 처리, 레거시 신규 기능의 에이전트 연동 기간을 수일에서 수분 단위로 단축

* 품질 향상: 동일 유형 실패 재발 감소, 진화 후 처음 보는 요청에서도 성공률 향상, Dry-run·승인·롤백으로 잘못된 데이터 변경 방지

* 비용 절감: LLM 호출 70% 이상 감소(스킬 축적에 따라 지속 감소)로 추론 비용 절감, 툴 래퍼 개발·실패 대응 공수 감소

### 범위 및 제약사항

* In Scope: Mock Legacy eWorks 구축(장애 주입기 포함), 레거시 모듈 자동 탐색·카드·어댑터 생성, Jev·LLM 하이브리드 라우팅, Code-as-Action 실행 런타임 및 안전장치, 하네스 레벨 자가 수정(어댑터·모듈 카드·프롬프트·임계값), 스킬 라이브러리, 검증 파이프라인 및 변경 이력 관리, 운영 UI

* Out of Scope: 실제 eWorks 레거시·운영 DB 연동, 레거시 원본 코드의 자동 수정, 모델 가중치 학습·파인튜닝, 운영 환경 코드의 무검증 자동 배포(최종 반영은 승인 절차 유지)

* 제약사항: 사내 실데이터 사용 불가로 목업 레거시·목업 데이터 기반 구축(현실성은 실제 레거시 경험 기반의 함정 설계로 보완), Jev는 외부 API로 사내망 반입 정책 확인 필요(대안: 오픈소스 SemIf 온프렘 구성), Jev 컨텍스트 32K 토큰 제한으로 도메인 → 모듈 계층형 판단 필요, 실행·자가 수정은 샌드박스와 스냅샷 DB에서만 수행

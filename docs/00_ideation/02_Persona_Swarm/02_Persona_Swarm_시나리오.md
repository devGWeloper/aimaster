### 핵심 사용자 시나리오

**시나리오 1 : 페르소나 군단 기반 배포 전 자동 테스트**

* ID : SC-001

* 상황 : 에이전트 개발자가 신규 기능 배포 전 품질을 검증할 때

* 목표 : 실제 사용자처럼 다양한 요청을 대량으로 던져 숨겨진 결함을 배포 전에 찾아내는 것

* 사전 조건 : 테스트 대상 에이전트 엔드포인트 연결, 대상 업무 도메인 설명 및 기능 목록 등록, 실패 유형 분류 체계 정의

* 상세 흐름

| 단계 | 사용자 행동 | 시스템 동작 | 비고 |
| --- | --- | --- | --- |
| 1 | 테스트 대상·기능 범위·페르소나 수 설정 | 직무·숙련도·말투·성격을 조합해 페르소나 자동 생성 | 예: 50명 |
| 2 | 테스트 실행 | 페르소나별 멀티턴 대화 동시 수행, 중간에 요구사항 변경·모호한 표현·오타 등 재현 | 병렬 실행 |
| 3 | - | Jev가 턴마다 응답 채점(의도 이해/정확성/위험 행동 여부) | 실시간 대시보드 |
| 4 | 결과 리포트 확인 | 실패 유형별 분류, 대표 대화 재현 링크, 심각도 순 정렬 | - |
| 5 | 결함 확인 후 회귀셋 편입 승인 | 실패 케이스를 회귀 테스트셋으로 자동 편입 | 1번 프로젝트 evolve셋 연계 |

* 입력 예시

```
[테스트 설정]
- 대상: eWorks Agent v1.3 (신규 기능: 출장비 정산 조회)
- 페르소나 수: 50
- 성격 분포: 급함 30%, 모호함 30%, 꼼꼼함 20%, 공격적 20%
- 대화 길이: 3~8턴

[생성된 페르소나 예시]
- P-017: 입사 1년차 생산관리, 줄임말 多, 급함
  "출장비 그거 어케됨? 지난번꺼"
```

* 기대 출력

```
[테스트 리포트]
- 실행 대화: 50건 / 총 312턴
- 발견 결함: 9건
  · [심각] 지시대명사("그거", "지난번꺼") 해석 실패 → 엉뚱한 건 조회: 4건
  · [중간] 요구사항 변경 시 이전 조건 유지 오류: 3건
  · [낮음] 응답 형식 불일치: 2건
- 되묻기 성공률: 41% (모호한 요청 22건 중 9건만 되물음)
- 회귀셋 편입 대기: 9건
```

* 성공 기준

  * 기준 1: 동일 대상 기준 수동 테스트 대비 3배 이상 결함 발견

  * 기준 2: 발견 결함의 80% 이상이 개발자 검토 시 실제 결함으로 확인(오탐 20% 이하)

**시나리오 2 : 반복 실행 기반 일관성 진단**

* ID : SC-002

* 상황 : 운영 중인 에이전트가 "가끔 실패한다"는 현업 피드백이 들어왔을 때

* 목표 : 어떤 과제가 불안정한지 정량적으로 찾아내고 개선 효과를 추적하는 것

* 사전 조건 : 대상 과제 테스트셋 구축, 반복 실행 횟수(k) 설정, 실행 환경 고정(동일 버전·동일 입력)

* 상세 흐름

| 단계 | 사용자 행동 | 시스템 동작 | 비고 |
| --- | --- | --- | --- |
| 1 | 진단 대상 과제셋과 반복 횟수 설정 | 과제별로 동일 페르소나·동일 입력으로 k회 반복 실행 | 기본 k=5 |
| 2 | - | 과제별 성공 횟수 집계, pass@1(평균)과 pass^5(전부 성공) 산출 | 일관성 격차 계산 |
| 3 | - | 불안정 과제(일부만 성공)에서 성공 실행과 실패 실행의 궤적 비교, 분기 지점 식별 | - |
| 4 | 진단 리포트 확인 | 불안정 과제 목록, 분기 원인, 성공 실행 기반 가이드라인 초안 제시 | 1번 프로젝트로 전달 |

* 입력 예시

```
[진단 설정]
- 대상 과제: 40개
- 반복 횟수: 5회
- 고정 조건: Agent v1.3, temperature 기본값
```

* 기대 출력

```
[일관성 진단 리포트]
- pass@1 (실행 기준 평균 성공률): 81.0%
- pass^5 (5회 모두 성공 과제 비율): 57.5%
- 일관성 격차: 23.5%p
- 불안정 과제 Top 3
  · T-12 "부서별 결재 현황 요약": 3/5 성공 — 툴 호출 순서가 실행마다 다름
  · T-27 "반려 사유 분석": 2/5 성공 — 집계 범위 해석 불일치
  · T-33 "정산 건 상태 조회": 4/5 성공 — 날짜 해석 오류 간헐 발생
- 가이드라인 초안: "집계 요청 시 기간을 먼저 확정한 후 조회 툴 호출"
```

* 성공 기준

  * 기준 1: 불안정 과제를 100% 식별하고 성공/실패 분기 지점을 제시

  * 기준 2: 가이드라인 적용 후 pass^5가 개선 전 대비 10%p 이상 향상

### 핵심 사용자 시나리오

**시나리오 1 : 자연어 지시 기반 운영 정책 변경 (What-if 검증 포함)**

* ID : SC-001

* 상황 : FAB 운영 담당자가 긴급 출하 대응을 위해 생산 우선순위를 바꿔야 할 때

* 목표 : 룰 수정 없이 자연어 한 문장으로 정책을 바꾸고, 반영 전 영향을 미리 확인하는 것

* 사전 조건 : 디지털트윈 FAB 가동 중(설비·로트·OHT·스토커 목업 구성), **RTS·MCS·MES·EAP·EES 5개 시스템이 MCP 서버 + UNS로 트윈에 연결되어 FAB 온톨로지·Temporal Knowledge Graph에 실시간 반영 중**, 정책 스키마(우선순위·부하 제한·홀드 조건 등) 정의, Jev 디스패칭 판단 연동 완료

* 상세 흐름

| 단계 | 사용자 행동 | 시스템 동작 | 비고 |
| --- | --- | --- | --- |
| 1 | 채팅창에 자연어 지시 입력 | LLM 에이전트가 MCP로 관련 시스템 조회(MES: 로트 상태·납기, EES: 식각 설비 건강도, MCS: 반송 대기) 후 지시를 타입이 정해진 정책·제약으로 변환해 표시 | 해석 오류 시 수정 가능, 근거 출처 시스템 표시 |
| 2 | 해석 결과 확인 | Temporal Knowledge Graph에서 현재 시점 스냅샷을 떠 What-if 시뮬레이션 실행(가속 모드), EES 센서는 시계열 파운데이션 모델로 예측 반영 | 실제 트윈은 영향 없음 |
| 3 | - | 지시 적용 전/후 KPI 비교 카드 제시(사이클타임·처리량·설비 부하·다른 로트 지연) | 부작용 하이라이트 |
| 4 | 승인 | 정책을 RTS(디스패칭)·MCS(반송 우선순위)에 MCP 제어 도구로 반영, Jev가 새 정책으로 이벤트마다 판단 | 맵 위 흐름 즉시 변화, 제어 이력 기록 |
| 5 | 모니터링 | 판단별 확신도 표시, 확신도 낮은 판단은 LLM 에스컬레이션(보라색 표시) | - |

* 입력 예시

```
"LOT-A123, A124, A127 핫랏으로 지정해서 오늘 18시 전에 출하되게 해줘.
 대신 식각 설비 부하는 85% 넘기지 마."
```

* 기대 출력

```
[참조 데이터]
- MES: LOT-A123/A124/A127 현재 ETCH-02 단계, 잔여 4~6 스텝
- EES: EQ-ETCH-04 챔버 압력 FDC 경고 추세 → 가용 설비에서 제외 권고
- MCS: ETCH 베이 스토커 적재율 78%

[지시 해석]
- priority_override: [LOT-A123, LOT-A124, LOT-A127] → HOT
- deadline: 2026-10-02 18:00
- constraint: equipment_group=ETCH, max_utilization=0.85

[What-if 결과]
- 핫랏 3개 예상 출하: 16:40 / 17:05 / 17:52 (모두 마감 내)
- 전체 처리량: -2.1%
- 일반 로트 평균 대기: +18분
- 식각 설비 최대 부하: 84%
- 주의: LOT-B209 납기 위험(예상 지연 25분)

[반영 후 모니터링]
- 판단 처리: 1,240건/분 (Jev 96.3%, LLM 에스컬레이션 3.7%)
```

* 성공 기준

  * 기준 1: 지시 입력부터 트윈 반영까지 1분 이내, 지시 해석 정확도 90% 이상

  * 기준 2: What-if 예측 KPI와 실제 반영 후 KPI의 오차 10% 이내

**시나리오 2 : 장애 발생 대응 및 위험 지시 차단**

* ID : SC-002

* 상황 : 설비 다운 등 돌발 상황이 발생해 운영 담당자가 급하게 대응 지시를 내릴 때

* 목표 : 장애 상황에서 빠르게 재스케줄링하되, 위험한 지시는 실행 전에 걸러지는 것

* 사전 조건 : 장애 시나리오 주입 기능(설비 다운·PM 돌입·스토커 만재 등) 구성, EAP 설비 이벤트·EES FDC 알람이 UNS로 실시간 발행 중, 위험 지시 판별 규칙 및 확인 절차 정의

* 상세 흐름

| 단계 | 사용자 행동 | 시스템 동작 | 비고 |
| --- | --- | --- | --- |
| 1 | (장애 발생 또는 재난 버튼으로 주입) | EAP 설비 다운 이벤트 수신 → MES에서 영향 로트, MES 레시피 정보로 호환 설비 조회 → 대체 설비 재배정 자동 수행 | Jev 실시간 판단 |
| 2 | 대응 지시 입력 | LLM이 지시 해석 후 위험도 판정(대량 홀드, 설비 제약 해제, 품질 조건 무시 등). MES 레시피 조건·EES 설비 상태를 근거로 판정 | - |
| 3 | - | 위험 지시면 실행 보류 및 영향 범위·위험 사유 제시 후 확인 요청 | 안전 지시는 바로 SC-001 흐름 |
| 4 | 수정 지시 또는 확인 | 수정된 지시로 What-if 실행 후 반영 | 이력 기록 |

* 입력 예시

```
[장애] EQ-PHOTO-03 다운 (예상 복구 4시간)

[지시] "포토 대기 로트 전부 다른 포토 설비로 돌리고, 레시피 안 맞는 설비도 그냥 써."
```

* 기대 출력

```
[장애 자동 대응]
- 영향 로트: 17개
- 대체 설비 재배정: 11개 (EQ-PHOTO-01, 02)
- 재배정 불가: 6개 (호환 레시피 설비 없음)

[위험 지시 감지 - 실행 보류]
- 사유: "레시피 미호환 설비 사용"은 품질 조건 위반
- 영향: 6개 로트 품질 리스크
- 대안 제시:
  ① 6개 로트 홀드 후 EQ-PHOTO-03 복구 대기 (예상 지연 4시간)
  ② 6개 로트 중 납기 임박 2개만 우선 대기열 최상단 배치
- 선택해 주세요.
```

* 성공 기준

  * 기준 1: 장애 감지 후 자동 재배정 완료까지 10초 이내(트윈 시간 기준)

  * 기준 2: 위험 지시 테스트셋의 95% 이상을 실행 전 차단·확인 요청

**시나리오 3 : 교차 시스템 원인 추적 (AI-Ready Data 실증)**

* ID : SC-003

* 상황 : 생산 관리자가 특정 로트가 왜 늦어지는지 알고 싶을 때. 지금은 MES·RTS·MCS·EAP·EES 화면을 각각 열어 시간을 맞춰가며 사람이 추적해야 함

* 목표 : 자연어 질문 한 번으로 5개 시스템 데이터를 엮어 원인과 근거를 받는 것

* 사전 조건 : 5개 시스템이 FAB 온톨로지로 엔티티 연결(Lot↔Carrier↔Equipment↔Recipe), Temporal Knowledge Graph에 이벤트 이력 축적, 시스템별 MCP 조회 도구 제공

* 상세 흐름

| 단계 | 사용자 행동 | 시스템 동작 | 비고 |
| --- | --- | --- | --- |
| 1 | 자연어로 질문 | LLM 에이전트가 질문을 엔티티(LOT-B209)와 기간으로 분해 | - |
| 2 | - | Temporal Knowledge Graph에서 해당 로트의 시점별 사실을 조회하고, 필요 시 MCP로 각 시스템 상세 조회 | 시스템 간 ID는 온톨로지가 자동 매핑 |
| 3 | - | 사건을 시간순 타임라인으로 엮어 원인 체인 제시, 각 사실에 출처 시스템·시각 표시 | 근거 없는 추론은 "추정"으로 구분 |
| 4 | 후속 지시 | 원인에 대한 대응 지시는 SC-001 흐름(What-if → 승인 → 반영)으로 연결 | - |

* 입력 예시

```
"LOT-B209 오늘 왜 이렇게 늦어? 원인이랑 해결 방법 알려줘."
```

* 기대 출력

```
[원인 타임라인 - LOT-B209]
- 09:12 [EES] EQ-CVD-02 히터 온도 FDC 경고 발생
- 09:15 [EAP] EQ-CVD-02 상태 RUN → DOWN (알람 코드 HTR-201)
- 09:16 [RTS] LOT-B209 디스패칭 대상에서 EQ-CVD-02 제외, EQ-CVD-01 대기열 5순위 배정
- 09:40 [MCS] CVD 베이 스토커 적재율 95% → LOT-B209 캐리어 반송 대기 38분
- 10:31 [MES] LOT-B209 CVD 스텝 시작 (계획 대비 +72분)

[원인 요약]
- 1차: EQ-CVD-02 다운(EES 경고 3분 후 발생 → 사전 감지 가능했음)
- 2차: 대체 설비 대기열 + 스토커 만재로 반송 지연 중첩

[제안]
- LOT-B209 우선순위 상향 시 납기 준수 가능 (What-if 실행할까요?)
- EQ-CVD-02 히터 FDC 경고 시 선제 대체 배정 정책 추가 권고
```

* 성공 기준

  * 기준 1: 교차 시스템 질의 테스트셋 정답률 85% 이상, 답변 내 모든 사실에 출처 시스템 표시

  * 기준 2: 질문부터 원인 타임라인 제시까지 30초 이내(사람 수동 추적 대비 시간 단축 측정)

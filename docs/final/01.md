# 프로젝트 개요

## 프로젝트명

**AutoQual Self-Evolving Agent: CodeAct와 Loop Engineering으로 스스로 생성·복구·진화하는 AutoQual 멀티 에이전트**

반도체 장비가 PM·부품 교체·알람으로 Down된 뒤 Seasoning·Qual 판정을 거쳐 다시 Up되기까지의 AutoQual 업무를 대상으로 한다. Super Agent가 기준정보·로그분석·레거시DB Agent를 편성해 Qual 계획, 판정, 승인 요청까지 처리하고, 필요한 Agent를 스스로 만들고(Grow), 깨지면 스스로 고치고(Heal), 쓸수록 판단 로직과 구조를 스스로 개선(Evolve)하며, 불필요해진 Agent는 안전하게 정리(Retire)하는 PoC를 구축했다.

## 배경 및 문제 정의

* **AutoQual 시간 = 장비 Down Time**: Leak Check → Seasoning → Qual 측정(Particle·ER·Uniformity) → Spec 판정 → Up 승인이 끝나기 전까지 장비는 생산을 하지 못한다. 가정한 라인(장비 30대·챔버 90개·PM 8종)에서는 연 약 1,000건의 AutoQual이 발생한다

* **손실의 절반 이상이 '판단'에서 생김**: 꼭 필요한 공정 시간은 약 2.5시간이지만, 엔지니어가 기준정보 시스템·FDC 화면·레거시 DB를 직접 오가며 판단을 준비하고(건당 1.5~2시간), 1차 Fail로 재작업(건당 3~4시간)하면 7~8시간이 된다. 같은 챔버·같은 PM에도 Seasoning 매수가 엔지니어별로 25~45매까지 갈린다

* **기존 자동화의 한계**

  | Pain Point | 현상 |
  | --- | --- |
  | 판단 실패 = 추가 Down | 1차 Pass율 약 70% 가정 시 연 약 300건 재작업, 약 1,000 챔버·시간 추가 정지 |
  | 판단이 숙련자 머릿속에만 | 3년치 Qual 이력 3,000건이 레거시 DB(약어 컬럼·미문서화 코드값)에 방치, 야간·주말은 확인할 사람 없음 |
  | 결과가 쌓여도 배우지 않음 | 기본 Seasoning 매수는 장비 도입 때 값 그대로, 같은 Fail 패턴이 반복돼도 시스템 판단은 불변 |
  | 조용히 깨지고 조용히 틀림 | 로그 포맷·DB 스키마·단위(mTorr→Torr) 변경 시 멈추거나 **에러 없이 틀린 값**을 냄 → 오판 Up 시 Lot Scrap |
  | 새 질문에 수 주, 기능은 쌓이기만 | 새 분석은 IT 개발 요청 대기, 한 번 만든 기능은 아무도 지우지 않아 중복·미사용 코드 누적 |

* **해결 방향**: 데이터를 연결하는 것만으로는 부족하다. 판단 로직 자체가 현장 결과로 계속 갱신되고, 환경 변화에 스스로 적응하며, 필요한 기능은 스스로 만들고 불필요한 기능은 스스로 정리하는 구조가 필요하다

## 목표 사용자

* 설비 엔지니어 — PM 후 AutoQual을 수행하고 장비 Up 여부를 판정
* 공정/Qual 담당자 — Qual Spec 관리, Qual 이력·Fail 원인 분석
* 에이전트 운영자 — Agent 생성·복구·진화 결과를 검토·승인

## 기술 스택

| 구분 | 선정 기술 | 역할 |
| --- | --- | --- |
| LLM | 사내 제공 API (`autoqual/llm.py` 어댑터, OpenAI·Anthropic 호환) — `claude-opus-5-5`(Agent 생성·Heal 패치·Evolve 변이), `claude-sonnet-5-5`(Super Agent 계획·종합), `claude-haiku-5-5`(엔티티 추출·요약) | 역할별 모델 분리. 미설정 시 오프라인 Playbook으로 결정적 재현 |
| Agent Framework | LangGraph (StateGraph + Subgraph + Checkpointer + interrupt) | L1/L2/L3 3중 루프, 측정 대기·사람 승인 interrupt |
| 행동 방식 | CodeAct — Agent가 작성한 Python 코드를 샌드박스에서 실행 | Agent 생성·자기 수정이 가능한 행동 단위 |
| 분기 판단 | Jev (보정 확률 의사결정 모델, 사내망 반입 전에는 로컬 보정 로지스틱 헤드) | 편성·오류 분류·진화 필요 여부를 확률 임계값으로 판단 |
| 판정 | 결정적 코드 `judge_qual` | Spec Pass/Fail은 LLM이 아닌 코드 |
| 저장소 | SQLite(WAL) — 운영 시 동일 스키마로 PostgreSQL | Agent Registry·경험 메모리·진화 아카이브·Lineage·감사 로그, RAG 미사용 |
| Output | Pydantic Structured Output | Agent 간 결과 스키마 고정 |
| 운영 UI | FastAPI + SSE / React 19 + Vite + Tailwind v4 + shadcn/ui + React Flow | 실시간 편성 맵·루프 트레이스·승인·진화 리포트 |
| 데이터 | Mock Fab (`mock_env/`, 시드 고정) | 장비 30·챔버 90·PM 8종, Qual 이력 3,000건/3년, 장애 주입기 |

결정적 판정 코드와 루프 밖에 고정한 평가 하네스를 결합해, Agent에게 자율성을 주면서도 판정·평가·권한은 Agent가 건드릴 수 없게 설계했다.

## 주요 기능

* **AutoQual 자율 처리** — 요청 한 줄("ETCH-07 B챔버 Wet Clean PM 끝났어. AutoQual 진행해줘")로 Super Agent가 하위 Agent를 편성해 Seasoning 매수 추천(근거: 교훈 ID·원천 이력) → 측정 → 결정적 판정 → 사람 승인 → Up까지 처리

* **Grow (Agent 자동 생성)** — 기존 Agent로 처리할 수 없는 요청이면 Agent Factory가 명세·코드·테스트를 작성하고, 스키마 탐색으로 자기 코드를 공격하는 엣지 케이스까지 통과해야 `probation`으로 투입

* **Heal (오류 자가 복구)** — 로그 포맷·스키마 변경으로 실패하거나 사후 검증(값 범위)에 걸리면 해당 항목만 "확인 불가"로 먼저 응답하고, 진단 CodeAct → 패치 → 회귀 테스트 → 버전 반영 → 같은 오류를 가진 Agent 연쇄 복구 후 재응답

* **Evolve (5계층 진화)** — ① 파라미터·교훈 ② 스킬 ③ Agent 코드 ④ Agent 구성(생성·병합·폐기) ⑤ Super Agent 편성 전략을 "변이 → 루프 밖 하네스 평가 → 선택(Held-out 비하락) → 아카이브 → Shadow → 승격/자동 롤백" 사이클로 개선

* **이력 리플레이 진화** — 3년치 Qual 이력 3,000건을 시간순으로 재생해 분기마다 진화하고 다음 분기로 검증(Walk-forward), 최근 6개월은 Held-out. Time-Travel Guard가 재생 시점 이후 데이터를 차단해 운영 첫날부터 3년 경험이 반영된 상태로 시작

* **Retire (불필요 Agent 정리)** — 장기 미사용·기능 대체 Agent를 의존성 분석 → 대체 검증 → `deprecated` 14일 유예(리다이렉트) → 사람 승인 → `retired` 아카이브 보관. 유사 요청이 다시 오면 새로 만들기 전에 아카이브에서 복원

* **안전장치** — 결정적 의도 가드, CodeAct 샌드박스(AST 검사·import 화이트리스트·권한 프록시·감사 로그), 읽기 전용 데이터, 사후 검증, 장비 상태 변경 사람 승인(무승인 변경 0건)

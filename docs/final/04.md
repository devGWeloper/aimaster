# KPI 달성도

## 측정 방법

* 측정 범위: Autopilot 전체 타임라인(ch00 초기 구축 → SC-006 리플레이 3,000건 → SC-001~005·007~009, 가상 시각 2026-07 ~ 2026-12, 운영 요청 320건)을 완주한 뒤 계산
* 계산 주체: `eval/kpi.py` — 루프가 접근·수정할 수 없는 고정 코드가 저장소·하네스 기록에서 계산. 재현은 `python -m eval.qa_suite --story` 한 번(최대 속도 364.5초, 결과 `eval/qa_result.json`), 운영 UI 「Fab·KPI」 화면·`/api/kpi`에서 같은 값 확인
* 조건: 시드 고정 목업 + 오프라인 Playbook(결정적 재현). 응답 시간은 목업 I/O 모델과 LLM 지연 모델을 합친 가상 응답 시간, MTTR은 가상 시각 기준
* 달성률 산정: 높을수록 좋은 지표는 실측 ÷ 목표, 낮을수록 좋은 지표(MTTR)는 목표 ÷ 실측, 0건 목표는 0건 유지 시 100%
* 기획서의 "진화 후 구조 개선(코드 중복률 50%↓, 응답시간 30%↓)"을 두 지표로 나눠 총 **16종**으로 측정했다

## 미달성 항목

* **미달성 KPI 없음** — 16개 지표 모두 목표를 달성했다.

다만 아래 항목은 목표 대비 여유가 작거나 측정 조건에 한계가 있어 해석에 주의가 필요하며, 사내 LLM 연동 후 재측정 대상이다.

* **목표 근접 항목 (여유 5% 이내)**
  * 오류 자가 복구율 — 70% → 71.4% (달성률 102%). 분모 7건 중 2건은 레거시 테이블 이관으로 데이터 자체가 없어 코드 수정으로 복구할 수 없는 건이며, 예산 안에서 조기 중단 → 운영자 에스컬레이션한 것은 설계대로의 동작이다. 표본이 작아 1건 차이로 목표를 밑돌 수 있다
  * Qual 1차 Pass율 — +15%p → +15.2%p (달성률 101%). 리플레이만으로는 +12.4%p(83.81%)였고, SC-007 운영 결과 학습(Focus Ring 사용시간 변수 추가)이 더해져 목표를 넘었다
  * Agent 호출 효율 — 20%↓ → 21%↓ (달성률 105%)

* **측정 조건의 한계**
  * 모든 수치는 오프라인 Playbook(실제로 실행되는 코드 후보, 일부는 의도적 결함 포함) 기준이라 실제 LLM의 코드 생성 품질·지연·비용이 반영되지 않았다
  * Jev는 사내망 반입 전 로컬 보정 로지스틱 헤드로 대체되어 판단 품질이 목업 분포에 묶여 있다
  * 응답시간·MTTR은 가상 시각이며, Qual 준비 시간의 수작업 기준(105분)은 가상 Fab 업무 흐름 추정치다
  * Agent 자동 생성 성공률의 분모는 미지원 요청 3건으로 표본이 작다
